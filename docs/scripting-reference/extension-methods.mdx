# Paracore Extension Methods

This guide provides an exhaustive reference for the global objects, session commands, and extension methods available within Paracore. Every method is designed to simplify the Revit API, providing "Magic" resolution for strings, units, and element identities.

:::info REPL & Gallery Parity
All extension methods work **identically** in the **REPL** (single-line and multi-line) and in **Gallery scripts** (full C# project structure). They were designed as shortcuts to simplify the verbose Revit API, but they are standard C# extension methods available everywhere the engine runs.
:::

---

## Global Context
These objects are automatically injected into every script and REPL session.

| Object | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| **`Doc`** | `Document` | The active Revit Document. | `Doc.Title` |
| **`UIDoc`** | `UIDocument` | The active Revit UI Document. | `UIDoc.ActiveView` |
| **`UIApp`** | `UIApplication` | The top-level Revit UI Application. | `UIApp.VersionBuild` |
| **`ActiveView`** | `View` | The currently active Revit view. | `ActiveView.Name` |
| **`Selection`** | `List<Element>` | Elements currently selected in Revit. | `Selection.Count` |
| **`Parameters`** | `Dictionary` | Parameters passed from the UI/Agent. | `Parameters["Mark"]` |
| **`Println(msg)`** | `void` | Prints to the Paracore Console. | `Println("Log message")` |
| **`Print(msg)`** | `void` | Alias for `Println`. | `Print("Log message")` |

## REPL Syntax Rules
To ensure successful execution in the REPL environment:
- **Semicolons**: Mandatory for variable assignments (`var rooms = GetElements<Room>();`), but optional for one-line queries (`Selection.Count`).
- **Count vs Count()**: Use the `.Count` property for immediate lists (e.g., `Selection.Count`, `GetMagicNames().Count`) and the `.Count()` method for dynamic enumerable queries (e.g., `GetElements<Wall>().Where(w => ...).Count()`).

## Discovery & Filtering
Find elements by name, category, or class without writing boilerplate collectors.

### `GetElements("Category")`
Gets instances or types of a specific category or family. Use the generic `FamilySymbol` for types.
- **Example**: `var doors = GetElements("Doors");` // All instances
- **Example**: `var types = GetElements<FamilySymbol>("Doors");` // All types

### `GetElements<T>(name)`
Gets elements filtered by C# class (e.g. `Wall`, `Room`).
- **Example**: `var walls = GetElements<Wall>();`
- **Example**: `var instances = GetElements<FamilyInstance>("Doors");`
- **Example**: `var all = GetElements<Element>();` // Gets EVERY element in the model.

### `GetElements(BuiltInCategory)`
Gets elements by Revit `BuiltInCategory` enum. Useful with hydrated enum parameters.
- **Example**: `var doors = GetElements(BuiltInCategory.OST_Doors);`

### `GetElement<T>(name)`
Finds a single element by its name or identity.
- **Example**: `var level = GetElement<Level>("Level 1");`

### `GetMagicNames()`
Lists all strings (categories, classes) that can be resolved by the engine.
- **Example**: `foreach(var n in GetMagicNames()) Println(n)`

### `GetCategories()`
Lists all Revit categories available in the active document.
- **Example**: `foreach(var c in GetCategories()) Println(c)`

## Parameter & Property Accessors (Instance-Level)
Paracore extends the Revit `Element` class with smart, unit-aware getters and setters. These read **instance parameters** and fall back to C# properties via Reflection. The element is already accessed — these methods read/write **parameter values** on that element.

### `GetStr(name)` / `GetStr(name, unit)`
**Smart String Getter.** Returns name (for IDs) or formatted string. Falls back to C# property via Reflection.
```csharp
wall.GetStr("Base Constraint")   // → "Level 1"
door.GetStr("Mark")              // → "D-101"
door.GetStr("HandFlipped")       // → "True" (via reflection)
wall.GetStr("Length", "mm")      // → "3600" (unit-converted)
```

### `GetVal(name)` / `GetVal(name, unit)`
**WYSIWYG Getter.** Returns the exact string shown in the Revit Properties palette, with optional unit conversion.
```csharp
wall.GetVal("Length")            // → "3600.0 mm" (as shown in Revit UI)
room.GetVal("Area")              // → "25.46 m²"
```

### `GetNum(name)` / `GetNum(name, unit)`
**Numeric Getter.** Returns the raw `double` in internal units, or converted to a specific unit.
```csharp
wall.GetNum("Length")            // → 11.811 (feet — internal units)
wall.GetNum("Length", "m")       // → 3.6 (meters)
room.GetNum("Area", "m2")       // → 25.46
floor.GetNum("Volume", "m3")    // → 0.72
```

### `GetInt(name)`
**Integer Getter.** Returns the integer value — also works for yes/no (boolean) parameters.
```csharp
wall.GetInt("Is External")       // → 1 (true) or 0 (false)
```

### `SetVal(name, value)`
**The Smart Setter.** Resolves unit-strings, names, and IDs automatically.
```csharp
wall.SetVal("Comments", "Reviewed")    // string
wall.SetVal("Base Offset", "500 mm")   // value string — unit parsed
wall.SetVal("Level", "Level 2")        // ElementId resolved by name
```

### `SetNum(name, value, unit)`
**Numeric Setter.** Explicitly sets value with unit conversion.
```csharp
wall.SetNum("Base Offset", 500, "mm")  // sets 500mm in Revit internal feet
wall.SetNum("Sill Height", 0.9, "m")
```

## Parameter Accessors (Type-Level)

:::tip When to use Type-Level Accessors
Many critical properties live on the **ElementType**, not the instance. For example, a door's **Width** and **Height** are type parameters — `GetNum("Width")` on the instance returns `0`, but `GetTypeNum("Width", "mm")` returns the correct value (e.g., `900.0`).
:::

Same signatures as the instance accessors, but they target the element's **ElementType** (e.g., Wall Type, Door Type).

| Method | Description |
|---|---|
| `element.GetElementType()` | Returns the ElementType element |
| `element.GetTypeStr(name)` | Type-level `GetStr` |
| `element.GetTypeStr(name, unit)` | Type-level `GetStr` with unit |
| `element.GetTypeNum(name)` | Type-level `GetNum` |
| `element.GetTypeNum(name, unit)` | Type-level `GetNum` with unit |
| `element.GetTypeInt(name)` | Type-level `GetInt` |
| `element.GetTypeVal(name)` | Type-level `GetVal` |
| `element.GetTypeVal(name, unit)` | Type-level `GetVal` with unit |

```csharp
// Door Width and Height are TYPE parameters
door.GetTypeNum("Width", "mm")           // → 900.0
door.GetTypeNum("Height", "mm")          // → 2100.0

// Wall type properties
wall.GetTypeStr("Wrapping at Inserts")   // → "Do not wrap"
wall.GetTypeVal("Width")                 // → "200.0 mm"
```

### `element.FamilyName()`
Returns the true Family Name for both Loadable and System families.

```csharp
door.FamilyName()   // → "M_Single-Flush"

```

### `element.Matches(pattern)`
**Fuzzy Name Matcher.** Returns `true` if the pattern is found in the element's Type Name OR Family Name (case-insensitive).


**Identity Resolver.** Converts an `ElementId`, `int`, or `long` directly to a Revit Element.
```csharp
var el = 123456L.ToElement(Doc);
var wall = someId.ToElement(Doc) as Wall;
```

## Element: Door & Window Orientation

Revit's native `ToRoom`/`FromRoom` properties swap when a door is flipped. These helpers are **stable** regardless of flip state — using geometric swing arc analysis to determine room relationships.

:::warning Swing-Based Detection
`RoomTo()` and `RoomFrom()` determine room relationships based on the **physical swing arc geometry** — the room the arc swings into is the "To" room. This is the most reliable geometric approach, but it may not always match the **architectural intent**. For example, in egress situations where code requires the door to swing toward the exit, the swing direction is opposite to the logical "entry" direction. In such cases, consider adding a shared parameter to explicitly tag the intended direction.
:::

### `fi.RoomFrom()` / `fi.RoomAccess()`
Returns the room on the **non-swing side** — the side the door swings away from. Stable regardless of flips.
```csharp
door.RoomFrom()      // → "Corridor"
door.RoomAccess()    // → "Corridor" (alias)
```

### `fi.RoomTo()` / `fi.RoomDestination()`
Returns the room the door **swings into** (based on swing arc geometry). Stable regardless of flips.
```csharp
door.RoomTo()           // → "Office 101"
door.RoomDestination()  // → "Office 101" (alias)
```

### `fi.Handing()`
Returns the handing code as seen from `RoomFrom()` — the non-swing side.

Since `RoomFrom()` is always the side the door swings **away from**, the observer always sees a **Push** door. This means `Handing()` will always return `LH` or `RH`:

| Code | Meaning |
|---|---|
| `LH` | Left Hand — hinges on the left as seen from `RoomFrom()` |
| `RH` | Right Hand — hinges on the right as seen from `RoomFrom()` |

```csharp
door.Handing()    // → "LH" or "RH"
```

### `fi.HingeSide()`
Returns `"Left"` or `"Right"` as seen from the Access Room.
```csharp
door.HingeSide()  // → "Right"
```

### `fi.IsHandFlipped()` / `fi.IsFacingFlipped()`
Direct wrappers for Revit's `FamilyInstance.HandFlipped` and `FamilyInstance.FacingFlipped`.
```csharp
door.IsHandFlipped()    // → true / false
door.IsFacingFlipped()  // → true / false
```

### `fi.FindSwingArc()`
Returns the largest `Arc` found in the door's geometry — the physical swing arc in World Space.
```csharp
var arc = door.FindSwingArc();
```

### `fi.IsStandardDoor()`
Returns `true` if the door is hosted in a standard wall (Basic/Stacked), `false` if it's a Curtain Wall panel (glass door).
```csharp
door.IsStandardDoor()  // → true for standard doors, false for curtain wall doors
```

### `.StandardOnly()` — Collection Filter
Filters a `FamilyInstance` collection to exclude Curtain Wall hosted panels. Curtain wall doors don't carry standard properties like Level, Width, Height, Room, or swing geometry.
```csharp
GetElements<FamilyInstance>("Doors")
    .StandardOnly()
    .Table();
```

## Collection: Filtering

All filtering methods are **generic** — they preserve the input type throughout the chain.

### `.WhereParam(name, value)` — String filter
Filters elements where the named parameter/property equals the value (case-insensitive).
```csharp
GetElements("Doors").WhereParam("Level", "Level 1")
```

### `.WhereParam(name, op, value)` — String predicate filter
Filters using string operations: `"contains"`, `"starts"`, `"ends"`.
```csharp
GetElements("Doors").WhereParam("Mark", "starts", "D-10")
GetElements("Rooms").WhereParam("Name", "contains", "Laundry")
```

### `.WhereParam(name, value, unit)` — Numeric filter
Filters elements where the named numeric parameter equals the value (tolerance: 0.001).
```csharp
GetElements<Wall>().WhereParam("Width", 200, "mm")        // exactly 200mm
```

### `.WhereParam(name, op, value, unit)` — Numeric comparison
Filters using comparison operators: `">"`, `"<"`, `">="`, `"<="`.
```csharp
GetElements<Room>().WhereParam("Area", ">", 25.0, "m2")   // larger than 25sqm
GetElements<Wall>().WhereParam("Length", "<", 10.0, "m")   // shorter than 10m
```

### `.WhereMatches(pattern)` — Fuzzy name filter
Filters to elements whose Type Name OR Family Name contains the substring (case-insensitive).
```csharp
GetElements("Doors").WhereMatches("Single-Flush")
GetElements("Windows").WhereMatches("Fixed")
```

## Collection: Sorting

### `.OrderByParam(name)` — Ascending
Sorts ascending. **Automatically uses numeric sort** for Double/Integer parameters.
```csharp
GetElements("Rooms").OrderByParam("Area").Table()       // smallest first
GetElements("Doors").OrderByParam("Mark").Table()       // alphabetical
```

### `.OrderByParamDesc(name)` — Descending
Sorts descending. Same auto-numeric detection.
```csharp
GetElements("Rooms").OrderByParamDesc("Area").Table()   // largest first
```

## Collection: Grouping & Aggregation

### `.GroupByParam(groupBy)` → Group | Count
Groups the collection by a parameter value and returns a summary table.
```csharp
GetElements("Doors").GroupByParam("Level").Table()
// Group        | Count
// Level 1      | 14
// Level 2      | 9
```

### `.GroupByParam(groupBy, sum, unit)` → Group | Count | Total
Groups by one parameter and sums a second numeric parameter per group.
```csharp
GetElements("Walls").GroupByParam("Base Constraint", "Length", "m").Table()
// Group   | Count | Total
// Level 1 | 23    | 284.5

GetElements("Rooms").GroupByParam("Level", "Area", "m2").Table()
```

### `.SumParam(name, unit)`
Returns the sum of a numeric parameter across the collection.
```csharp
double totalLength = GetElements("Walls").SumParam("Length", "m");
double totalArea   = GetElements("Rooms").SumParam("Area", "m2");
```

## Collection: Bulk Write

### `.SetParam(name, value)`
Sets a parameter on **every element** in the collection inside a single transaction. Returns the collection (chainable).
```csharp
GetElements("Doors")
    .WhereParam("Comments", "")
    .SetParam("Comments", "Pending Review")
```

:::note
All updates are wrapped in a single `Transact` call — one undo step in Revit.

## Collection: Coordination & Clash Detection

### `.AuditClashes(targetCategory)` / `.AuditClashes(target, tolerance)`
**Production-grade interference detection.** Detects geometric intersections between source elements and a target category.

:::caution Tolerance Units (Feet vs Strings)
There are two ways to specify tolerance (the minimum overlap required to report a clash):
- **String (`string`)**: Evaluated using Paracore's unit-aware converter. For example, `tolerance: "2mm"` is automatically converted to the correct internal units for you. This is the **recommended** approach.
- **Raw Number (`double`)**: Evaluated in **Revit internal units (feet)**. For example, `tolerance: 0.05` means a minimum overlap of 0.05 feet. Do **not** use `tolerance: 2.0` expecting 2mm, as that means 2 feet (609.6 mm) and will hide almost all minor clashes!
:::

```csharp
// Basic clash audit (0 tolerance, reports all intersections)
GetElements("Walls").AuditClashes("StructuralColumns").Table();

// Recommended: Unit-aware string tolerance (requires at least 2mm overlap)
GetElements("Walls")
    .AuditClashes("StructuralColumns", tolerance: "2mm")
    .Table();

// Advanced: Raw number tolerance (requires at least 0.05 feet overlap)
GetElements("Walls")
    .AuditClashes("Pipes", 0.05)
    .Table();
```

**Output:** Renders an interactive **Coordination Grid** with clickable element IDs and 3D helper geometry. Click a row to zoom to the exact clash point in Revit.

### `Doc.ClearClashHelpers()`
Clears all visual clash helper geometry (red pillars and solids) from the Revit document. 

:::tip Auto-Cleanup
You usually do not need to call this manually. Every time you run `.AuditClashes()`, Paracore automatically deletes the previous clash helpers before generating new ones, and they are protected with a unique internal `CORE_CLASH` identifier so standard generic models are never accidentally deleted. However, this method is useful if you want to cleanly wipe the view after finishing your coordination review.
:::

```csharp
// Clear all clash geometry from the model
Doc.ClearClashHelpers();
```

## Unit Conversions & Snapping

### `InputUnit(unit)`
Converts a human value *to* Revit internal units.
- **Example**: `var target = 1500.InputUnit("mm");`

### `OutputUnit(unit)`
Converts internal units *from* feet/sqft to a human unit.
- **Example**: `var mm = val.OutputUnit("mm");`

### `FormatUnit(unit)`
Returns a formatted string with the unit suffix (e.g. `"1500.0 mm"`).
- **Example**: `val.FormatUnit("mm");`

### `FormatValueOnly(unit)`
Returns the numeric value in the target unit as a string, **without** the unit suffix. Ideal for CSV/Excel export.
- **Example**: `val.FormatValueOnly("mm");` → `"1500"`

### `RoundTo(unit)`
Snaps the internal value to the nearest incremental precision of the unit.
- **Example**: `val.RoundTo("mm");`

### `"dimensionString".ToMeters()`
Parses a dimension string with a unit suffix and returns the value in meters.
- **Example**: `"500mm".ToMeters()` → `0.5`
- **Example**: `"2ft".ToMeters()` → `0.6096`

**Supported Unit Strings:**

| Unit String | Meaning |
|---|---|
| `mm`, `cm`, `m`, `ft`, `in` | Length |
| `m2`, `sqm`, `ft2`, `sqft` | Area |
| `m3`, `cum`, `ft3`, `cuft` | Volume |

## Precision-Aware Math
Always use these fuzzy comparison methods for Revit geometry.

| Method | Description | Example |
| :--- | :--- | :--- |
| **`.AlmostZero()`** | Checks if value is effectively 0. | `if (val.AlmostZero()) ...` |
| **`.IsAlmostEqualTo(v)`** | Fuzzy equality check (1e-9). | `val.IsAlmostEqualTo(target)` |
| **`.IsLessThan(limit)`** | Strictly less than (ignores noise). | `val.IsLessThan(limit)` |
| **`.IsGreaterThan(limit)`** | Strictly greater than (ignores noise). | `val.IsGreaterThan(limit)` |
| **`.IsLessThanOrEqual(limit)`** | Less than or approx. equal. | `val.IsLessThanOrEqual(limit)` |
| **`.IsGreaterThanOrEqual(limit)`** | Greater than or approx. equal. | `val.IsGreaterThanOrEqual(0)` |
| **`.IsPositive()`** | Strictly positive (> 1e-9). | `val.IsPositive()` |
| **`.IsNegative()`** | Strictly negative (< -1e-9). | `val.IsNegative()` |
| **`.Round(decimals)`** | Fluent rounding. | `val.Round(2)` |

| `SetExecutionTimeout(seconds)` | Extend script timeout beyond default 10s |
| `GetElements(BuiltInCategory)` | Query by `BuiltInCategory` enum |
| `Show(type, data)` | Low-level structured output |
| `Table(data)` / `BarChart(data)` / `PieChart(data)` / `LineChart(data)` | Global visualization helpers |

## REPL Cookbook: Multi-Line Workflows

These multi-line snippets demonstrate real-world workflows. Paste them into the REPL or use them in Gallery scripts — they work identically in both.

### Door Schedule with Type Dimensions
```csharp
GetElements<FamilyInstance>("Doors")
    .StandardOnly()
    .OrderByParam("Mark")
    .Select(d => new {
        Mark    = d.GetStr("Mark"),
        Level   = d.GetStr("Level"),
        Width   = d.GetTypeVal("Width"),
        Height  = d.GetTypeVal("Height"),
        From    = d.RoomFrom(),
        To      = d.RoomTo(),
        Handing = d.Handing(),
        Hinge   = d.HingeSide()
    })
    .Table();
```

### Room Area Report by Level
```csharp
// Summary: group rooms by level, sum areas
GetElements("Rooms")
    .GroupByParam("Level", "Area", "m2")
    .Table();
```

### Find and Flag Unreviewed Doors
```csharp
// Set "Pending Review" on all doors with empty Comments
GetElements("Doors")
    .WhereParam("Comments", "")
    .SetParam("Comments", "Pending Review");

Println($"Flagged {GetElements("Doors").WhereParam("Comments", "Pending Review").Count()} doors.");
```

### Structural Wall Audit (Width ≥ 300mm)
```csharp
GetElements<Wall>()
    .Where(w => w.GetNum("Width", "mm") >= 300)
    .OrderByParamDesc("Width")
    .Select(w => new {
        Name   = w.Name,
        Level  = w.GetStr("Base Constraint"),
        Width  = w.GetVal("Width"),
        Length = w.GetVal("Length")
    })
    .Table();
```

### Sustainability Dashboard
```csharp
// Carbon + U-Value audit for exterior walls
GetElements<Wall>()
    .WhereParam("Function", "Exterior")
    .Select(w => new {
        Name   = w.Name,
        Area   = w.GetNum("Area", "m2"),
        Carbon = Math.Round(Eco.GetCarbon(w), 2),
        UValue = Math.Round(Eco.GetUValue(w), 3)
    })
    .Table();

// Live project weather
var weather = Eco.GetWeather();
Println($"Site: {weather.Temperature}°C, Wind: {weather.WindSpeed} km/h");
```

### Clash Detection Workflow

```csharp
// Basic: walls vs pipes
GetElements("Walls")

    .Table();

GetElements("StructuralColumns")

```

### Sequential Renumbering
```csharp
// Renumber Level 2 doors sequentially
int i = 1;
GetElements("Doors")
    .WhereParam("Level", "Level 2")
    .OrderByParam("Mark")
    .SetParam("Mark", e => $"D2-{i++:000}");
```
