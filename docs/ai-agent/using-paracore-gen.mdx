# Using Paracore-Gen

This is the end-user guide to **Paracore-Gen** — the optional connector that lets an AI assistant drive Revit through natural language. It is the human-facing counterpart to [How Paracore-Gen works](./how-it-works.mdx), which covers the implementation and safety internals.

You do not need any of this to use the REPL or Gallery scripts — those run your own code and are documented elsewhere.

## 1. What Paracore-Gen is

Paracore-Gen connects an AI assistant to your open Revit model. You ask for things in plain language, and the assistant finds the answer or makes the change for you. It works by running short C# scripts against your open project using Paracore's own simplified commands, such as `GetElements("Walls")`, `.WhereParam(...)` and `.SetParam(...)`. It can also render a view as an image to check its own work.

It is an optional, separate installer. The platform works fully without it. See [AI Assistants and MCP](./index.mdx) for what you can connect it to.

Example requests:

- "How many doors are on Level 2?"
- "Set Comments to 'Fire-rated' on all walls with a 2 hr rating."
- "Show me the total wall area by level."

## 2. Before you start

- Revit is open with a project loaded.
- The Paracore server inside Revit is switched on.
- Your AI client is connected to Paracore-Gen.
- Supported AI clients: Claude Desktop, Cursor, VS Code, or any client that speaks MCP.
- Supported Revit versions: the versions supported by the Paracore Add-in (the current Add-in is v4.8.3 — see the Add-in release page for the exact Revit-year list).

## 3. Install and connect

Paracore-Gen is a standalone Windows app. You install it once, then tell your AI client where it lives and restart the client. The rest of this section covers both steps.

### Install Paracore-Gen

Paracore-Gen is installed alongside the other Paracore tools. Its files live here:

```
C:\Users\seyou\AppData\Roaming\paracore-data\mcp-servers
```

The server program is `paracore-gen.exe` in that folder. (On any Windows machine the per-user path is `%APPDATA%\paracore-data\mcp-servers\paracore-gen.exe`, where `%APPDATA%` expands to `C:\Users\<your-user>\AppData\Roaming`.)

### Add it to your AI client

Paracore-Gen is an MCP server, so connecting it means adding a `paracore-gen` entry to your client's MCP config and restarting the client. The JSON shape is identical for every MCP client — only the config file location changes.

**Claude Desktop**

1. Open **Settings → Developer** and click **Edit Config**. This opens the folder that holds `claude_desktop_config.json` (normally `%APPDATA%\Claude\claude_desktop_config.json`).
2. Open that file and add `paracore-gen` under `mcpServers`:
   ```json
   {
     "mcpServers": {
       "paracore-gen": {
         "command": "C:\\Users\\seyou\\AppData\\Roaming\\paracore-data\\mcp-servers\\paracore-gen.exe"
       }
     }
   }
   ```
   No `args` are required — the server runs over stdio. If the file already lists other servers, just add the `"paracore-gen": { ... }` block inside the existing `mcpServers` object and keep the commas correct.
3. Save the file and **fully quit Claude Desktop** (close it from the system tray too, not just the window), then start it again. Claude Desktop only reads the config at launch, so a partial quit is the usual reason a new server never appears.
4. Start Revit, open a project, and make sure the Paracore server inside Revit is switched on.
5. In a new chat, confirm `paracore-gen` shows up in the tools list (the tools/connectors icon in the message box), then ask: "Check that you can connect to Revit." The assistant should report that it is connected and tell you which project is open.

**Cursor and VS Code**

Both speak MCP and use the same JSON shape. Cursor reads `~/.cursor/mcp.json`; VS Code reads `.vscode/mcp.json` in your workspace (or the user `settings.json` `mcp` block). Drop the same `mcpServers` block in, then restart the client.

### Verify the connection

At the start of every session the assistant runs a connection check (`ping`). It reports one of four states:

| State | Meaning | Fix |
|---|---|---|
| Connected | Everything works. | Nothing to do. |
| Server up, no document | Revit is open but no project is loaded. | Open or load a project. |
| Revit running, no connection | The in-Revit Paracore server is off. | Turn the Paracore server on in Revit. |
| Revit not running | Revit is closed. | Start Revit. |

When genuinely connected, the assistant also receives a quick-start cheat sheet it uses for the rest of the session.

## 4. Your first request

1. Open a project in Revit.
2. Ask the assistant a simple question, for example: "How many walls are in the model?"
3. The assistant first looks at your active view, your current selection and your levels (via `get_context`). This means "these walls" or "this level" refers to what you have selected or have open.
4. You get the answer, often as an interactive table.

## 5. What it can do

**Find and filter elements.** By category, parameter value, text contained in a parameter, or numeric comparison (for example, area greater than 25 m²). Example: "List doors whose Mark contains 'GEN'."

**Group, count and sum.** Example: "Total room area per level."

**Read parameters.** Instance and type parameters, in the units you ask for (mm, cm, m, m²). Values are exact; rounding is only applied for display.

**Change the model.** Set parameters, set numeric values with units, bulk edit, delete, hide, unhide and isolate. Example: "Set the Top Offset of all walls on Level 1 to -150 mm."

**Show results.** Tables and charts. The desktop app renders them in its **Analytics** tab — `.Table()`, `.BarGraph()`, `.PieGraph()` and `.LineGraph()` are the engine methods that produce them. When an assistant drives Paracore there is no desktop tab: the assistant returns the data and your client (Claude Desktop, Cursor, VS Code) renders the table or chart natively.

**See the model.** Render any view as an image, with or without dimensions and tags. The assistant uses this to look at what it built or changed — it cannot otherwise see Revit's screen. Example: "Show me the 3D view."

**Explore unknown elements.** List every parameter an element has, its built-in properties and a summary of its geometry.

**Doors and windows.** Room from/to, handing, and standard doors vs. curtain-wall doors.

**Materials and units.** Filter by material, and convert between units automatically.

## 6. Reading the results

- Large tables are summarized: when there are 50 rows or fewer, all rows are shown; above that, the first 50 rows plus the last 2 are shown, and the full total is always reported. Narrow your request instead of paging through results.
- Parameter-list tables (every parameter of an element) are always shown in full.
- Charts are produced by the engine methods `.BarGraph()`, `.PieGraph()` and `.LineGraph()` and render in the desktop app's **Analytics** tab. Driven by an assistant, the same data comes back to the client, which displays the table or chart itself — there is no separate Paracore tab in that case.
- A picture of a view hides dimensions and room tags by default. Ask for the version that keeps tags if you need them.

## 7. Making changes safely

- **Changes are committed immediately**, and the old values are not saved automatically.
- Ask the assistant to **show the current values first** and to **report old → new** after the change.
- **Type parameters affect every element of that type.** Changing the width of one window's type changes all windows of that type. To change only one element, ask the assistant to create a new type for it first.
- **Moving geometry can change other things**: rooms, hosted doors and windows, and joins. Check the counts afterwards.
- If Revit shows a warning while the assistant is working, the [dialog watcher](./how-it-works.mdx#the-dialog-watcher) answers it so the request can finish, and the assistant reports what was pressed. Set `PARACORE_WATCH_DIALOGS=0` before starting your AI client to answer dialogs yourself.
- Save your project or work on a copy before large edits.

## 8. Limits and good-to-know behavior

- Scripts stop automatically after **90 seconds** by default. Long jobs can be given more time or split into smaller steps. A single very long framework operation may not be interrupted by the timeout — if Revit stops responding, restart Revit to clear it.
- Exploring data is read-only. If a script tries to write while exploring, the change is rolled back.
- If Revit is busy, wait for it to finish instead of sending the request again.
- A misspelled parameter name gives an error, not a blank or zero value.
- A category with no elements in the model returns zero. It does not fall back to the types.

## 9. Troubleshooting

| Problem | Likely cause | What to do |
|---|---|---|
| "No connection" | Revit or the Paracore server is not running. | See the connection states in section 3. |
| "Parameter not found" | Wrong parameter name. | Ask the assistant to list the parameters for that category. |
| Table is too wide or empty | No columns were chosen. | Ask for specific columns. |
| Image has no dimensions or room tags | They are hidden by default. | Ask for the view with tags kept. |
| Request times out | The job is too large. | Ask for it in smaller steps. |
| "Revit is busy" | Another operation is still running. | Wait, then ask again. |

## 11. FAQ

**Does it change my model without asking?**
No. You approve the code before it runs, and there is a one-time consent dialog per Revit session. Nothing changes unseen. For bulk changes, ask it to show old → new values so you can verify.

**Does it work on workshared models?**
Workshared and very large models are untested — the connector has been exercised against small single-user models. Use caution and work on a copy.

**Can it create new geometry?**
It can create and modify elements by dropping to the raw Revit API when the high-level methods are not enough, but the generalist assistant specializes in reading, filtering and editing existing elements. Deep modeling (massing, families) is the job of separate specialist servers.

**Where does my data go?**
Whatever you send to the AI assistant is handled under that provider's privacy policy. Paracore itself does not send your model data to a server, and tool output deliberately omits your Windows user name and Revit install path — only the project file path is included so the assistant knows which model it is in. You see and approve the code before it runs.
