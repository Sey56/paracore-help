# Using Paracore-Gen

Paracore-Gen connects an AI assistant to your open Revit model. You describe the job; it writes and runs a C# script against the active project, using Paracore shortcuts, LINQ or the raw Revit API — whichever the task needs. Optional: the REPL and Gallery work without it. [How it works](./how-it-works.mdx) covers the internals.

Use Claude Desktop, Cursor, VS Code or any MCP client.

## Get started

**You need:** Revit open with a project, the Paracore server inside Revit switched **ON**, and an AI client connected to Paracore-Gen. Supported Revit versions are listed on the [Downloads](../getting-started/downloads.md) page.

### Install and connect

Paracore-Gen is a standalone Windows app installed alongside the other tools. The server program is `paracore-gen.exe` in:

```
%APPDATA%\paracore-data\mcp-servers
```

`%APPDATA%` is your roaming folder — usually `C:\Users\<your-username>\AppData\Roaming`. Most MCP clients do not expand environment variables in JSON config, so paste the resolved path.

Add a `paracore-gen` entry to your client's MCP config, then restart the client. The JSON shape is the same everywhere; only the config file location changes.

**Claude Desktop**

1. **Settings → Developer → Edit Config** opens the folder holding `claude_desktop_config.json` (normally `%APPDATA%\Claude\claude_desktop_config.json`).
2. Add `paracore-gen` under `mcpServers`:

   ```json
   {
     "mcpServers": {
       "paracore-gen": {
         "command": "C:\\Users\\<your-username>\\AppData\\Roaming\\paracore-data\\mcp-servers\\paracore-gen.exe"
       }
     }
   }
   ```

   Replace `<your-username>` with your Windows username, or paste the full path from File Explorer. No `args` are needed — the server runs over stdio. If other servers are already listed, add the `"paracore-gen": { ... }` block inside the existing `mcpServers` object and keep the commas correct.
3. **Fully quit Claude Desktop** — including the system tray — and start it again. It reads the config only at launch; a partial quit is the usual reason a new server never appears.
4. Start Revit, open a project and switch the Paracore server ON.
5. In a new chat, confirm `paracore-gen` appears in the tools list, then ask: "Check that you can connect to Revit." It should report the connected state and the open project.

**Cursor and VS Code**

Cursor reads `~/.cursor/mcp.json`; VS Code reads `.vscode/mcp.json` in the workspace (or the `mcp` block in user `settings.json`). Drop in the same `mcpServers` block and restart the client.

### Connection states

At the start of every session the assistant runs a connection check (`ping`):

| State | Meaning | Fix |
|---|---|---|
| Connected | Everything works. | Nothing to do. |
| Server up, no document | Revit is open but no project is loaded. | Open or load a project. |
| Revit running, no connection | The in-Revit Paracore server is off. | Turn it on in Revit. |
| Revit not running | Revit is closed. | Start Revit. |

When connected, the assistant also receives a short cheat sheet it uses for the rest of the session.

![An AI client connected to paracore-gen, showing the loaded tools and the active project, view and levels](/img/ai-gen-connect-check.png)

### Your first request

1. Open a project in Revit.
2. Ask: "How many walls are in the model?"
3. The assistant first checks your active view, selection and levels, so "these walls" or "this level" means what you have selected or open.
4. The answer comes back, often as an interactive table.

## If something goes wrong

| Problem | Likely cause | What to do |
|---|---|---|
| "No connection" | Revit or the Paracore server is not running. | Check the connection states above. |
| "Parameter not found" | Wrong parameter name. | Ask it to list the parameters for that category. |
| Table is too wide or empty | No columns were chosen. | Ask for specific columns. |
| Image has no dimensions or room tags | Hidden by default. | Ask for the view with tags kept. |
| Request times out | The job is too large. | Ask for it in smaller steps. |
| "Revit is busy" | Another operation is still running. | Wait, then ask again. |

## What to ask for

There is no fixed list of commands — every request is answered by code written for it. Counting, filtering, grouping, parameter reads (in mm, cm, m, m²), bulk edits, charts and views all work, including multi-step work that creates geometry.

- **Find and filter** — category, parameter value, text or number. "List doors whose Mark contains 'GEN'."
- **Group, count and sum** — "Total room area per level."
- **Change the model** — set parameters, bulk edit, delete, hide, unhide, isolate. "Set the Top Offset of all walls on Level 1 to -150 mm."
- **Show results** — tables and charts. The engine's `.Table()`, `.BarGraph()`, `.PieGraph()` and `.LineGraph()` produce the data; your client renders it. There is no desktop Analytics tab when an assistant drives Revit.
- **See the model** — render any view as an image. The assistant uses this to check its own work. Dimensions and room tags are hidden by default; ask for them if needed.
- **Explore unknown elements** — list every parameter, built-in property and a geometry summary.
- **Doors and windows** — room from/to, handing, standard vs. curtain-wall doors.
- **Materials and units** — filter by material, convert units automatically.

More prompts to copy: "How many doors are on each level?" · "Which rooms have no name?" · "Find walls where Comments is empty." · "Set Mark on all doors to the room they open from." · "Hide all temporary generic models." · "Bar chart of room area by level." · "Pie chart of doors by type." · "Show me Level 1 with dimensions and tags."

## Reading the results

- Tables of 50 rows or fewer show every row; above that, the first 50 and last 2 are shown, with the full total always reported. Narrow the request instead of paging.
- Parameter-list tables are always shown in full.
- Charts come back as data that your client renders; no Paracore tab is involved.
- Values are exact; rounding is applied only for display.

## Working safely

- **Changes commit immediately.** Old values are not saved automatically. Ask to see current values first and an old → new report afterwards.
- **Type parameters affect every element of that type.** To change one element, ask for a new type first.
- **Moving geometry can change rooms, hosted doors and windows, and joins.** Check the counts afterwards.
- If Revit shows a warning mid-request, the [dialog watcher](./how-it-works.mdx#the-dialog-watcher) answers it and the assistant reports what was pressed. Set `PARACORE_WATCH_DIALOGS=0` before starting the client to answer dialogs yourself.
- Save the project or work on a copy before large edits.

## Limits

- Scripts stop after **90 seconds** by default. Long jobs can be given more time or split up. A single very long framework operation may not be interrupted — if Revit stops responding, restart it.
- Exploring data is read-only; a write attempt during exploration is rolled back.
- If Revit is busy, wait rather than resending the request.
- A misspelled parameter name gives an error, not a blank or zero value.
- A category with no elements returns zero; it does not fall back to the types.

## FAQ

**Does it change my model without asking?**
No. You approve the code before it runs, with a one-time consent dialog per Revit session. For bulk changes, ask for an old → new report.

**Does it work on workshared models?**
Workshared and very large models are untested; the connector has been exercised on small single-user models. Use a copy.

**Can it create new geometry?**
Yes — through the raw Revit API (`Wall.Create`, family instances, transactions) whenever the shortcut methods are not enough. You still see and approve the code first.

**Where does my data go?**
What you send is handled under your AI provider's privacy policy. Paracore itself does not send model data to a server. Tool output omits your Windows user name and Revit install path; only the project file path is included. You see and approve the code before it runs.
