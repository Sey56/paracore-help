# Interactive REPL (BIM Laboratory)

The **Paracore REPL** (Read-Eval-Print Loop) is a persistent C# playground with direct, real-time access to the Revit API and Paracore's high-level helpers. It is one editor — not a "quick command box" plus a "proper script box". You type C#, press <kbd>Ctrl</kbd>+<kbd>Enter</kbd>, and the session answers.

## One editor

There is a single input, in the **Console** tab, below the execution history. It runs **whatever is in it**:

- one expression — `Doc.Title`
- one statement — `var walls = GetElements<Wall>();`
- a twenty-line snippet with a `foreach` and a local function
- a whole script, including its `Params` class

Nothing is classified as "single-line" or "multi-line" work, because there is no separate mode to be in. Press <kbd>Enter</kbd> for a new line; press <kbd>Ctrl</kbd>+<kbd>Enter</kbd> — or click **Run** — to execute the whole buffer. A one-line command and a two-hundred-line draft follow exactly the same rules, and the difference between them is only how much you typed.

### Saving and loading

The editor reads and writes plain `.cs` files: **Load**, **Save**, **Save As**, and **New**. There is no required folder structure and no metadata block — a REPL snippet is a file you can keep, mail, or paste into a Gallery script later. When you are done experimenting, **New** clears the editor and unloads the file, so a draft never overwrites something you meant to keep.

## The echo

The single most useful behaviour in the whole tool: **the last expression in the editor is printed back to you.**

```csharp
"Paracore"
```

→ `Paracore`

```csharp
GetElements<Wall>().Count()
```

→ `42`

```csharp
GetElements<Wall>()
```

→ a numbered list, `01 - Basic Wall (359588)`, `02 - …`, capped at 50 with a note telling you to use `.Table()` for the full set.

```csharp
GetElements<Wall>().Table()
```

→ an interactive table in the **Summary** tab, and the raw list is suppressed underneath it.

That is the whole read-eval-*print*: you do not need `Println` to see an answer, and you do not need to save a file to ask a question. **Echo to peek; `.Table()` to read.**

> [!NOTE]
> The semicolon decides. `Doc.Title` is an expression, so its value is yours to see. `Doc.Title;` is a statement, and statements have no value to print. This is ordinary C# — the REPL does not invent behaviour, it just shows you the result of what you typed.

## Shared context between turns

The session is persistent. A variable defined in one turn is alive in the next, which is how you build something up over several turns instead of writing one enormous script and hoping:

```csharp
// turn 1
var rooms = GetElements<Room>();
Println($"Found {rooms.Count} rooms");
```

```csharp
// turn 2 — `rooms` is still here
rooms.WhereParam("Level", "Level 1").Table()
```

| Command | Effect |
| :--- | :--- |
| `vars` (or `list`) | list every variable alive in the session |
| `reset` (or `clear vars`) | wipe the session state without restarting Revit |
| `inspect rooms` | formatted tree of one variable, safe for Revit elements |

<img src={ConsoleHistory} alt="REPL session history: each turn with the result it produced" />

The **History** tab keeps every turn — the code and the result — so a session is a readable transcript you can scroll back through and re-run.

## Scripting rules

A REPL turn is a top-level script. That means:

- **No `class Program`, no `Main()`, no namespace** — write statements.
- **`using` statements are allowed** and rarely needed; the common Revit and LINQ namespaces are already imported.
- **Classes go at the end.** If you paste a script with a `Params` class, it belongs after the top-level statements — which is also where the engine reads your form from.
- **Variables persist; types do not.** A class defined in a turn is available to later turns, but redefining it is easier than fighting it. (`reset` clears everything.)

```csharp
var limit = 2.5.InputUnit("m");

var tall = GetElements<Wall>()
    .Where(w => w.GetNum("Unconnected Height") > limit);

tall.Table();
tall.Select().Zoom();
```

## Global reference

These are injected into every turn, script, and Gallery script.

| Object | Type | Description |
| :--- | :--- | :--- |
| **`Doc`** | `Document` | The active Revit database Document. |
| **`UIDoc`** | `UIDocument` | The Revit UI Document (active window). |
| **`UIApp`** | `UIApplication` | The Revit application. |
| **`ActiveView`** | `View` | The active view. |
| **`Selection`** | `List<Element>` | Elements currently selected in Revit. |
| **`Parameters`** | `Dictionary<string, object>` | Parameters passed from the UI or an agent. |
| **`Println(msg)`** | `void` | Console output, with `$"…"` interpolation. |

## Reading and writing, without the boilerplate

| Method | Returns | Notes |
| :--- | :--- | :--- |
| **`GetStr(name)`** | `string` | Resolves an ElementId to its **name** (so `GetStr("Level")` is `"Level 1"`, not `255432`). |
| **`GetNum(name)`** | `double` | Internal units (feet / sq ft) — for arithmetic. |
| **`GetNum(name, unit)`** | `double` | Converted, **exact** (`"mm"`, `"m2"`, …). |
| **`GetVal(name)`** | `string` | Formatted exactly as Revit's Properties palette shows it. |
| **`GetInt(name)`** | `int` | Yes/no checkboxes → 1 / 0. |
| **`SetVal(name, value)`** | — | The smart setter: parses units, ids and strings. Opens its own transaction. |
| **`SetNum(name, num, unit)`** | — | Explicit unit-aware numeric setter. |

## Discovery

```csharp
var doors = GetElements("Doors");                 // door instances
var types = GetElements<FamilySymbol>("Doors");   // door types
GetElement("Level 1").Select()                    // one element, chained into the UI
GetMagicNames().Count                             // how many targetable names exist
GetElements<Element>()                            // everything — bulk audits
```

:::tip[Target everything]

`Element` is the base class of every Revit object, so `GetElements<Element>()` is the widest net there is. Combine it with `WhereCategory` or `WhereMaterial` instead of enumerating categories by hand.
:::

## Visualization

| Command / Method | Type | Description |
| :--- | :--- | :--- |
| **`Table(data)`** | Global | Renders a grid. Returns `void` (not chainable). |
| **`.Table()`** | Extension | Renders a grid and returns the collection — chainable. |
| **`.BarGraph()`** / **`.PieGraph()`** / **`.LineGraph()`** | Extension | Charts the collection; supply items with `name` and `value`. |
| **`.Select()`** / **`.Zoom()`** / **`.Isolate()`** | Extension | Drive the Revit UI from any collection. |

<img src={AnalyticsCharts} alt="Charts rendered from a REPL query" />

```csharp
// walls per level, as a bar chart
var data = GetElements<Wall>()
    .GroupBy(w => w.GetStr("Level"))
    .Select(g => new { name = g.Key, value = g.Count() })
    .ToList();

BarGraph(data);
```

## Recipes

### An element audit

Elements further than a kilometre from the origin are almost always CAD-import debris:

```csharp
var limit = 1000.InputUnit("m");

var lost = GetElements<Element>().Where(e =>
{
    var bb = e.get_BoundingBox(null);
    if (bb == null) return false;
    var centre = (bb.Min + bb.Max) / 2.0;
    return centre.DistanceTo(XYZ.Zero) > limit;
}).ToList();

Println($"{lost.Count} element(s) far from the origin");
lost.Select();      // and Revit jumps to them
```

### Door → room, in one pass

```csharp
GetElements<FamilyInstance>("Doors")
    .StandardDoor()
    .Select(d => new
    {
        Mark    = d.GetStr("Mark"),
        From    = d.RoomFrom(),
        To      = d.RoomTo(),
        Handing = d.Handing()
    })
    .Table();
```

### Room areas by level

```csharp
PieGraph(GetElements<Room>()
    .Where(r => r.GetNum("Area") > 0)
    .GroupBy(r => r.GetStr("Level"))
    .Select(g => new { name = g.Key, value = Math.Round(g.Sum(r => r.GetNum("Area", "m2")), 1) })
    .ToList());
```
