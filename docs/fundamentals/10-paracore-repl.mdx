# Paracore REPL

The **REPL** (Read-Eval-Print Loop) is your interactive BIM laboratory: a persistent C# session with live access to the Revit model. It is where you should explore anything you are not sure about before you commit it to a script.

## 1. One editor, one Run

The REPL lives in the **Console** tab, under the execution history. There is a single editor and no modes:

- **Type anything.** One expression, one statement, or a whole script with a `Params` class at the end.
- **<kbd>Ctrl</kbd>+<kbd>Enter</kbd> (or the Run button) executes the whole buffer.** <kbd>Enter</kbd> only adds a line.
- **Load / Save / Save As** read and write plain `.cs` files, so a draft can outlive the session. **New** clears the editor and unloads the file, so experimenting never overwrites a snippet you kept.

The size of what you type changes nothing about how it runs. There is no separate place for a "quick command" and no separate place for "real code".

## 2. The echo — why this feels like a conversation

**The last expression in the buffer is printed back to you.**

```csharp
"Paracore"                       // → Paracore
GetElements<Wall>().Count()      // → 42
GetElements<Wall>()              // → 01 - Basic Wall (359588), 02 - … (first 50)
```

`Println` is unnecessary for inspection — but a **semicolon** turns an expression into a statement, and a statement has no value to print:

```csharp
Doc.Title                        // echoes the project name
Doc.Title;                       // does nothing visible
```

Collections echo as a numbered list, capped at 50 with a hint that `.Table()` will show all of it. That is the division of labour: **echo to peek, `.Table()` to read.**

## 3. Rules worth knowing

**Semicolons.** Required to end a declaration (`var rooms = GetElements<Room>();`); optional for a final expression you want to see.

**`.Count` vs `.Count()`.** Both are legal on the lists the engine returns. Inside a LINQ chain (`Where`, `Select`) use `.Count()`; on a list you already have, `.Count`. If in doubt, `.Count()` always compiles.

**Variables persist.** Turn 2 can use what turn 1 declared:

```csharp
var rooms = GetElements<Room>();          // turn 1
rooms.WhereParam("Level", "Level 1").Table()   // turn 2 — `rooms` is still alive
```

**Session commands** (typed as-is, no semicolons): `vars` / `list`, `reset` / `clear vars`, `inspect rooms`.

**`using` statements are allowed** and usually unnecessary — the common namespaces are already imported. Classes go at the **end** of the buffer, exactly as in a script.

## 4. Discovery

```csharp
var doors = GetElements("Doors");                  // door instances
var types = GetElements<FamilySymbol>("Doors");    // door types
GetElement("Level 1").Select()                     // chain straight into the UI
GetMagicNames().Count                              // how many targetable names exist
```

No `FilteredElementCollector`, no `BuiltInCategory`, no `.Cast<T>()`.

## 5. Using it well

**Inspect before you assume.** `Selection[0].Peek()` is a Properties palette you can read from code — the fastest way to learn what a category's parameters are actually called. `Selection[0].CombinedParams().Table()` shows instance and type parameters side by side.

**Work in steps.** A query, then a filter, then a table, then a selection — four turns, each one verifiable. The session holds the intermediate result, so you never rewrite the query to add the next step.

```csharp
// turn 1: narrow
var limit = 2.5.InputUnit("m");
var tall = GetElements<Wall>().Where(w => w.GetNum("Unconnected Height") > limit);

// turn 2: look
tall.Table();

// turn 3: act
tall.Select().Zoom();
```

**Then keep it.** When the turns have converged on what you wanted, save the buffer as a script in the Gallery and give it a `Params` class — that is the path from question to tool.
